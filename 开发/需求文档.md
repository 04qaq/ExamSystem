# 在线考试系统 — 需求文档（与当前实现对齐）

本文档依据仓库内 **exam-server（Go API）** 与 **exam-client（Vue3 + Wails v3 桌面端）** 的现有能力整理，描述产品范围、角色与功能边界。

---

## 1. 项目概述

### 1.1 目标

为学校或培训机构提供一套「题库 → 组卷 → 发布 → 在线答题 → 客观题自动评分 → 主观题教师批阅 → 成绩查询与导出」的闭环能力。

### 1.2 部署形态


| 组件                     | 说明                                                                        |
| ---------------------- | ------------------------------------------------------------------------- |
| **考试服务（exam-server）**  | 独立 HTTP API 服务，连接 MySQL，提供全部业务接口与局域网发现能力。                                 |
| **桌面客户端（exam-client）** | 嵌入 Vue 静态资源的 Wails 程序（`ExamSystem.exe`），通过 HTTP 调用考试服务；支持自动发现服务地址与用户手动配置。 |
| **浏览器（可选）**            | 同一套 Vue 前端可单独 `vite` 构建部署或通过代理访问 API；发现逻辑与桌面端略有差异（见开发文档）。                 |


### 1.3 不在当前版本的需求范围（可选扩展）

以下能力**未**作为单独模块实现或未在界面暴露，若后续需要可作为迭代需求：

- 学生自助「找回密码 / 邮箱验证」类流程（管理员可通过更新用户重置密码）。
- 班级、选课、按班级投放试卷等教务维度模型（当前试卷对全局已发布且在时间窗内的学生可见）。
- HTTPS 终止、双机热备、Kubernetes 编排（部署由运维环境决定，代码侧为单体 HTTP 服务）。
- 独立的防作弊管控后台（当前仅记录提交时的切屏次数快照）。

## 2. 角色与权限


| 角色值 | 名称  | 核心能力                                                                  |
| --- | --- | --------------------------------------------------------------------- |
| 1   | 管理员 | 用户列表、创建用户、更新用户（姓名、角色、状态、密码）、查看操作日志。                                   |
| 2   | 教师  | 题库 CRUD、批量导入题目、试卷全流程（选题、随机抽题、发布/下架、复制、预览）、待批阅列表、主观题打分、成绩统计与 Excel 导出。 |
| 3   | 学生  | 查看可考试卷、开考、答题与保存答案、交卷、查看成绩列表与答题详情。                                     |


认证方式：**JWT（Bearer Token）**；注册接口默认创建 **学生** 角色账号。

## 3. 功能需求

### 3.1 认证与账号

- **注册**：用户名、密码、可选姓名；用户名唯一。
- **登录**：用户名 + 密码；禁用用户不可登录。
- **会话**：服务端签发访问令牌；前端持久保存 Token 并在请求头携带。
- **密码**：存储为 bcrypt 哈希；管理员更新用户时可传入新密码明文（由服务端哈希）。

### 3.2 题库（教师）

- **题型**：单选、多选、判断、填空、简答（与后端常量一致）。
- **题目字段**：题干、选项（JSON，选择题使用）、标准答案、默认分值、难度、标签、创建者。
- **操作**：分页列表、按条件筛选、创建、查看、更新、删除。
- **批量导入**：通过接口提交结构化题目数组（非上传 Excel 文件解析；条目数量有上限约束）。

### 3.3 试卷（教师）

ss

- **试卷属性**：标题、说明、考试时长（分钟）、总分、开考/结束时间、状态（草稿 / 已发布 / 已关闭）。
- **组卷**：向试卷添加题目并设定各题分值与排序；支持随机抽题接口按规则抽取入库题目。
- **生命周期**：发布、下架、复制试卷；预览（教师查看试卷题目构成）。
- **业务规则**：学生仅可在「已发布」且当前时间落在 `[start_time, end_time]` 的试卷上参加考试。

### 3.4 考试（学生）

- **试卷列表**：展示当前可用的已发布试卷；对已开考未提交的试卷返回可进行中的考试记录 ID。
- **开考**：创建或使用已有「进行中」考试记录；返回题目列表（**题目顺序随机**）、选择题 **选项顺序随机**（不少于三项时打乱）、剩余秒数（由开考时间与试卷时长推算）。
- **答题**：按题目提交答案；服务端 **内存缓存 + 数据库 UPSERT 双写**，降低意外丢失风险。
- **交卷**：合并缓存后对所有客观题自动判分；填空与简答题得分默认为 0，`is_correct` 为空表示待批阅；记录提交时间与简要行为快照（如切屏次数，由客户端上报）。
- **成绩**：分页列表与单场详情（含各题得分、正误、主观题批阅备注等）。

### 3.5 批阅与统计（教师）

- **待批阅**：列出需要教师处理的提交记录（含主观题进度）。
- **打分**：对主观题（填空、简答）录入得分与备注；完成后更新考试记录状态与总分。
- **统计**：按试卷查看统计数据；支持导出 **Excel**。

### 3.6 管理（管理员）

- **用户**：分页列表；创建用户（用户名、密码、角色、姓名）；更新用户（姓名、角色、启用/停用、可选重置密码）。
- **日志**：分页查看关键操作日志（含操作者、动作、目标对象、IP、时间等）。

## 4. 客户端体验需求（桌面端 / Web）

- **连接**：启动后自动尝试发现考试服务；支持在「网络设置」中手动填写服务根地址、测试连接、保存。
- **登录 / 注册**：统一入口；登录后按角色进入对应菜单。
- **通用**：布局侧栏导航、深浅主题切换（若已实现）、401 自动退回登录页。
- **发布版**：Windows 可执行文件建议使用无控制台子系统构建，界面文案避免暴露内部实现细节（如具体探测端口说明等）。

## 5. 非功能需求（与实现现状）


| 类别     | 说明                                                                  |
| ------ | ------------------------------------------------------------------- |
| **数据** | MySQL 持久化；核心实体包含用户、题目、试卷、试卷题目关联、考试记录、答题明细、操作日志。                     |
| **安全** | JWT 鉴权；路由按角色拦截；密码 bcrypt；CORS 中间件（跨域场景按需配置）。生产环境须更换默认 JWT 密钥与数据库口令。 |
| **发现** | 服务端在固定端口响应局域网发现请求；客户端同源 `/discover`（桌面）或浏览器内扫描（Web）。具体端口与协议见开发文档。   |
| **性能** | 答案批量刷盘间隔、缓存条目上限可由配置文件调整；高并发场景需结合部署与压测再定指标。                          |


---

## 6. 验收要点（建议）

1. 管理员创建教师 / 学生账号；禁用学生后无法登录。
2. 教师完成题库 → 组卷 → 发布；学生在时间窗内完整走完开考、保存、交卷流程。
3. 客观题分数与正误符合答案规则；主观题进入待批阅，教师打分后总分与状态正确。
4. 统计与导出 Excel 可用。
5. 桌面客户端在未手动配置时，能与同网段考试服务完成发现并成功调用 `/api/ping` 后的业务接口。
