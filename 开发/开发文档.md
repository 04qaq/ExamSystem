# 在线考试系统需求文档

## 1. 项目概述
本项目旨在构建一个在线考试平台，支持教师创建与管理题目、灵活组建试卷，学生在线参加考试并自动判分。服务端采用 Go 语言实现 RESTful API，客户端为 Wails 桌面应用程序（Vue3 + Go 内嵌 WebView）。

## 2. 用户角色
- **管理员**：系统维护、用户管理。
- **教师**：题库管理、试卷管理、查看考试成绩。
- **学生**：参加考试、查看本人成绩。

## 3. 功能需求

### 3.1 用户与认证模块
- 用户注册、登录（JWT 认证）。
- 角色分配（管理员、教师、学生）。
- 个人信息修改与密码重置。

### 3.2 题库管理模块（教师）
- 支持题型：单选题、多选题、判断题、填空题、简答题。
- 题目 CRUD：
  - 创建题目：题干、选项（选择题）、正确答案、分值、难度、标签（知识点）。
  - 编辑、删除、查询题目（分页、按题型/难度/标签筛选）。
- 批量导入题目（Excel/CSV）。

### 3.3 试卷管理模块（教师）
- 创建试卷：试卷标题、考试时长、总分、开始/结束时间、适用班级/学生。
- 组卷方式：
  - 手动选题：从题库选择题目加入试卷。
  - 随机组卷：指定题型、数量、难度分布，系统自动抽取。
- 试卷预览、修改、删除、发布/撤销发布。
- 试卷复制功能。

### 3.4 学生考试模块
- 学生端可见已发布的且处于有效时间内的试卷列表。
- 进入考试：
  - 倒计时显示，到时自动提交。
  - 答题界面：题目顺序展示，标记未答题，可翻页/跳题。
  - 答案保存（前端暂存 + 后端定时保存机制，防止丢失）。
- 提交试卷：提前交卷需二次确认；时间结束强制提交。
- 客观题（单选、多选、判断）自动判分；主观题（填空、简答）标记为待批阅。

### 3.5 成绩与批阅模块
- 学生查看本人成绩及答题详情（客观题对错，主观题待批阅状态）。
- 教师批阅主观题：查看答案，输入得分，提交后合计总分。
- 教师查看成绩统计：按试卷统计平均分、分数段分布、题目正确率等。
- 导出成绩为 Excel。

### 3.6 管理功能
- 管理员：班级/学生批量导入，用户状态管理。
- 系统日志：记录关键操作。

## 4. 非功能需求
- **性能**：支持 1000 并发考试，提交试卷响应时间 < 2 秒。
- **安全**：防作弊（切屏检测、随机题目顺序与选项顺序），HTTPS 传输，SQL 注入/XSS 防护。
- **可用性**：7x24 小时高可用，服务端支持水平扩展。
- **数据一致性**：答案实时保存，确保不丢失。
- **可维护性**：代码分层清晰，RESTful API，接口文档完善。

# 在线考试系统详细开发文档

## 1. 技术栈
- **服务端**：Go 1.21+, Gin 框架, GORM (MySQL), JWT, Zap 日志。纯 API，无前端页面。
- **客户端**：Wails v3（Go）+ Vue3 + TypeScript，通过 WebView 运行桌面应用，通过 HTTP/JSON 与服务端 API 通信，使用 Axios 作为 HTTP 客户端。
- **数据库**：MySQL 8.0，初始库名 `exam_system`。
- **答案缓存**：内存 `sync.Map` 暂存答题草稿，定时批量刷入 MySQL 持久化。

## 2. 系统架构
采用服务端 API + 桌面客户端分离模式，服务端负责全部业务逻辑与数据持久化，客户端（Wails 桌面应用）负责界面交互与用户操作。

```
[Wails 桌面客户端 (Vue3 WebView)]
         │
         │ HTTP/JSON (Axios)
         ▼
[Go API 服务器集群]
         │
    ┌────┴────┐
    ▼         ▼
[MySQL]   [sync.Map 答案缓存]
```

服务端内部采用分层架构：
- **Controller/Handler**：接收 HTTP 请求，参数校验，调用 Service。
- **Service**：业务逻辑。
- **Repository/DAO**：数据访问层（GORM）。
- **Model**：数据模型定义。
- **Middleware**：认证、授权、日志、限流、跨域等。
- **Utils**：工具函数、JWT、响应封装。

## 4. API 设计（RESTful，部分示例）

**认证模块**
- `POST /api/auth/register` – 注册
- `POST /api/auth/login` – 登录返回 JWT

**用户管理（管理员）**
- `GET /api/admin/users` – 用户列表
- `PUT /api/admin/users/:id/role` – 修改角色

**题库管理（教师）**
- `GET /api/teacher/questions?type=&difficulty=&tag=&page=&size=` – 分页查询
- `POST /api/teacher/questions` – 新建题目
- `PUT /api/teacher/questions/:id` – 编辑
- `DELETE /api/teacher/questions/:id` – 删除
- `POST /api/teacher/questions/import` – 批量导入（Excel解析）

**试卷管理（教师）**
- `POST /api/teacher/papers` – 创建试卷
- `PUT /api/teacher/papers/:id` – 修改试卷基本信息
- `POST /api/teacher/papers/:id/questions` – 手动添加题目
- `POST /api/teacher/papers/:id/random-select` – 随机选题
- `PUT /api/teacher/papers/:id/publish` – 发布
- `GET /api/teacher/papers/:id/preview` – 预览试卷

**学生考试**
- `GET /api/student/papers?status=published` – 可考试卷列表
- `GET /api/student/papers/:id/start` – 开始考试（创建 exam_record，返回题目及答案暂存）
- `POST /api/student/exam/:record_id/answer` – 保存/更新某题答案（实时保存）
- `POST /api/student/exam/:record_id/submit` – 提交试卷
- `GET /api/student/exam/records` – 成绩列表
- `GET /api/student/exam/records/:id` – 成绩详情

**批阅与统计**
- `GET /api/teacher/exam/records?paper_id=` – 待批阅列表
- `PUT /api/teacher/exam/details/:detail_id/grade` – 主观题打分
- `GET /api/teacher/statistics/paper/:paper_id` – 试卷统计

## 5. 开发要点与关键逻辑

### 5.1 认证中间件
- 使用 `github.com/golang-jwt/jwt` 生成 JWT，包含用户ID和角色。
- 中间件验证 JWT 并注入上下文。
- 角色鉴权中间件：检查 `role` 是否符合路由所需的权限。

### 5.2 组卷随机选题实现
教师提交随机组卷参数示例：
```json
{
  "rules": [
    {"type":1, "count":10, "difficulty":[1,2], "totalScore":30},
    {"type":3, "count":5, "difficulty":2, "totalScore":10}
  ]
}
```
服务端利用 MySQL `ORDER BY RAND()` 或收集所有符合条件的题目 ID，随机选取（配合事务确保证卷题目不重复）。生成 `paper_questions` 并计算总分。

### 5.3 学生考试流程
1. 学生请求开始考试，后端检查：
   - 试卷已发布，当前时间在 start_time 和 end_time 之间。
   - 该学生是否已有未提交的 record（如果是，则返回进行中的考试，防止重复创建）。
2. 若无进行中记录，创建 `exam_records`，状态为“进行中”，start_time 为当前时间。根据 `paper_questions` 生成答题结构，可将题目顺序和选项顺序随机打乱（防作弊），返回给前端。
3. 前端展示考试界面，每次选择答案调用 `POST /api/student/exam/:record_id/answer`，后端将答案写入内存缓存 `sync.Map`（key: `exam:answer:<record_id>:<question_id>`），后台 goroutine 每 30 秒批量将缓存中的答案 UPSERT 至 `answer_details` 表持久化。
4. 提交时，将缓存中该 record 的全部答案最终刷入 `answer_details`，客观题逐题比对 `questions.answer` 计算得分，更新 `exam_records` 总分和状态为“已提交”，随后从缓存中清除该 record 的答案。
5. 倒计时处理：前端倒计时，后端在 record 上记录开始时间+时长计算剩余时间，过时则后端强制提交（定时扫描或客户端提交时校验）。

### 5.4 防作弊措施
- 试卷题目顺序随机（保存到 paper_questions 的排序每次考试随机生成）。
- 选择题选项随机排列：返回题目时，按乱序后的选项数组返回，答案映射关系服务端处理。
- 切屏检测：前端监听 visibilitychange，记录切出次数，超过阈值可提示或标记（后端需增加字段记录可疑行为）。
- 考试期间禁止复制、右键菜单。

### 5.5 批阅主观题
教师查看某份记录的细节，主观题显示学生答案和题目标答（参考），教师输入得分并提交。更新 `answer_details.score_gained`，全部批阅后更新 `exam_records.status=3`（已批阅）并重算总分。

### 5.6 数据库迁移与种子数据
- 使用 GORM AutoMigrate 自动创建表。
- 编写 seed 脚本创建默认管理员账号。

## 7. 部署方案
- 服务端编译为二进制，使用 Docker 容器化，Nginx 反向代理。
- 客户端编译为独立可执行文件（Wails 打包），分发给教师、学生、管理员使用。
- MySQL 主从复制。
- 利用 GitHub Actions 或 Jenkins 实现 CI/CD。
- 日志收集：将日志输出到 stdout，配合 ELK 或 Loki 抓取。

## 8. 测试与验收标准
- 单元测试覆盖 Service 层核心逻辑（组卷、判分）。
- 接口测试使用 Postman/curl 验证所有 API。
- 压力测试：使用 wrk 或 k6 模拟 1000 并发请求，验证试卷列表、提交答案等接口。
- 功能验收：教师创建试卷→发布→学生考试→自动判分→教师批阅主观题→成绩查看全流程通过。
