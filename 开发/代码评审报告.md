## 1. 安全问题

### 1.1 [严重] 前端硬编码默认凭据

**文件**: `client/frontend/src/views/Login.vue:53`  
**代码**: `const form = reactive({ username: 'admin', password: 'admin123' })`  
**问题**: 登录表单默认填入 `admin/admin123` 作为占位值。生产环境部署时可能被恶意用户直接利用。  
**建议**: 移除默认值，使用空字符串初始化。

### 1.2 [严重] 后端硬编码种子用户密码

**文件**: `exam-server/scripts/seed.go:18-20`  
**代码**: `admin123`, `123456`, `student123` 在源码中硬编码  
**问题**: 这些密码永久存在于 Git 历史中，若仓库泄露则攻击者可直接登录系统。  
**建议**: 从环境变量或配置文件读取种子密码。

### 1.3 [严重] 用户禁用后仍可登录

**文件**: `exam-server/internal/service/auth_service.go:57-91`  
**问题**: `Login` 方法未检查 `user.Status` 字段。被禁用的用户（status=0）仍能获取 JWT Token 访问系统。  
**建议**: 登录时增加 `user.Status != 1` 的校验。

### 1.4 [高] CORS 允许所有来源

**文件**: `exam-server/internal/middleware/cors.go:9`  
**代码**: `Access-Control-Allow-Origin: *`  
**问题**: 任何网站都可跨域请求 API。虽然不会自动携带凭据，但增加了攻击面。  
**建议**: 生产环境限制为具体域名。

### 1.5 [高] 无速率限制

**文件**: `exam-server/internal/router/router.go:25-26`  
**问题**: `/api/auth/register` 和 `/api/auth/login` 无速率限制，可被暴力破解。  
**建议**: 接入限流中间件（如 `gin-limiter`）。

### 1.6 [中] Controller 中不安全的类型断言

**文件**: `exam-server/internal/controller/admin_controller.go:62,90`  
**代码**: `username.(string)` — 单返回值类型断言  
**问题**: 若 JWT 中间件缺失 `username` 键，会直接 panic。  
**建议**: 使用 `c.GetString("username")` 或 `username, ok := c.Get("username")`。

### 1.7 [中] 无登出/Token 吊销机制

**文件**: `exam-server/internal/utils/jwt.go`  
**问题**: 没有登出接口，JWT 一旦签发在过期前无法吊销。  
**建议**: 引入 Token 黑名单机制（Redis 或数据库）。

### 1.8 [中] 前端硬编码 API 地址

**文件**: `client/frontend/src/api/request.ts:5`  
**代码**: `baseURL: 'http://localhost:8080/api'`  
**问题**: 无法通过环境变量切换 API 地址，且使用明文的 HTTP。  
**建议**: 使用 `import.meta.env.VITE_API_BASE_URL` 并提供默认值。

### 1.9 [低] 无 CSRF 保护

**文件**: `client/frontend/src/api/request.ts:1-33`  
**问题**: Axios 实例仅添加 Bearer Token，无 CSRF Token 机制。  
**建议**: 对非 GET 请求添加 `X-XSRF-TOKEN` 头。

## 2. Bug 风险

### 2.1 [严重] 整数除法导致分数错误

**文件**: `exam-server/internal/service/paper_service.go:223`  
**代码**: `perScore := rule.TotalScore / rule.Count`  
**问题**: 整数除法丢弃余数。如总分 10 分 3 题，每题得 3 分，总计 9 ≠ 10。  
**建议**: 将余数分配到前几题，或改用浮点计算后四舍五入。

### 2.2 [严重] 试卷提交缺少事务

**文件**: `exam-server/internal/service/exam_service.go:166-256`  
**问题**: `SubmitExam` 在循环中逐条更新 `answer_details`（lines 230-235），然后更新 `exam_record`（lines 246-247）。未包裹在事务中。若记录更新失败，答案已写入但考试状态仍为"进行中"，数据不一致。  
**建议**: 将整个判分流程用 GORM Transaction 包裹。

### 2.3 [严重] 随机组卷缺少事务

**文件**: `exam-server/internal/service/paper_service.go:236-243`  
**问题**: `ClearByPaperID` 删除所有题后调 `BatchCreate`。若 `BatchCreate` 失败，试卷变为空题。  
**建议**: 用事务包裹。

### 2.4 [严重] 双重软删除机制冲突

**文件**: `exam-server/internal/model/question.go:33,36` + `exam-server/internal/repository/question_repo.go`  
**问题**: `Question` 模型同时有 `IsDeleted int8` 和 `DeletedAt gorm.DeletedAt`。GORM 的软删除（基于 `deleted_at`）从未被触发，而是手动 UPDATE `is_deleted = 1`。新查询忘记加 `Where("is_deleted = 0")` 会返回已删除数据。  
**建议**: 移除 `IsDeleted` 字段，只使用 GORM 的 `DeletedAt` 机制。

### 2.5 [高] 大量静默忽略错误

**文件**: `exam-server/internal/service/paper_service.go`（8 处），包括：  
- line 262: `qCnt, _ := s.pqRepo.GetMaxSortOrder(id)` — 数据库错误时 qCnt=0，阻塞发布流程  
- line 268: `actualTotal, _ := s.pqRepo.CalcTotalScore(id)` — 失败返回 0，误判总分不一致  
**建议**: 不要忽略这些错误，传播给调用者处理。

### 2.6 [高] 考试剩余时间忽略试卷结束时间

**文件**: `exam-server/internal/service/exam_service.go:370-371`  
**代码**: 
```go
elapsed := time.Since(record.StartTime)
remaining := int(paper.Duration)*60 - int(elapsed.Seconds())
```
**问题**: 余时仅从开始时间按时长计算，忽略 `paper.EndTime`。若学生在考试结束前 5 分钟开始 60 分钟考试，会显示剩余 55 分钟（实际只有 5 分钟）。  
**建议**: 取 `duration` 计算的剩余时间和 `EndTime - Now` 的较小值。

### 2.7 [高] 缓存刷新竞争条件

**文件**: `exam-server/internal/cache/answer_cache.go:63-76`  
**问题**: `FlushRecord` 在释放锁后才调用 `saveToDB`。释放锁到保存完成之间，并发 `Set` 写入的数据可能在下次刷新时丢失。  
**建议**: 在锁内复制数据，释放锁后操作副本。

### 2.8 [中] 前端空类型断言（运行时报错）

**文件**: `client/frontend/src/views/student/ExamTaking.vue:183`  
**代码**: `const currentQuestion = computed(() => questions.value[currentIndex.value] || {} as ExamQuestion)`  
**问题**: 题目列表为空时返回 `{}`，后续访问 `.type`、`.content` 等属性返回 `undefined`，引发渲染错误。  
**建议**: 在模板中用 `v-if="questions.length > 0"` 保护，或在 computed 中返回带默认值的对象。

### 2.9 [中] CSS 选择器缺少点号

**文件**: `client/frontend/src/views/teacher/PaperList.vue:215`  
**代码**: `modal-overlay { position: fixed; ... }`  
**问题**: 缺少 `.` 前缀，该样式从未生效，模态框无遮罩层。  
**建议**: 改为 `.modal-overlay`。

### 2.10 [中] `delete` 在 reactive 对象上可能不触发响应性

**文件**: 
- `client/frontend/src/views/teacher/PaperForm.vue:255`
- `client/frontend/src/views/teacher/PaperQuestions.vue:175`  
**代码**: `delete selectedScores[q.id]`  
**问题**: Vue 3 `reactive` 使用 Proxy，`delete` 可以工作，但模式脆弱。  
**建议**: 使用 `Reflect.deleteProperty` 或将值设为 0。

### 2.11 [中] localStorage 写入无 try/catch

**文件**: `client/frontend/src/views/student/ExamTaking.vue:388`  
**问题**: `localStorage.setItem` 在隐私模式下可能抛出异常，且位于 deep watcher 回调中，异常不会被捕获。  
**建议**: 包裹 try/catch。

### 2.12 [低] 单选按钮 `v-for` 的 key 使用值而非唯一 ID

**文件**: `client/frontend/src/views/student/ExamTaking.vue:53`  
**代码**: `<label v-for="opt in parsedOptions" :key="opt" ...>`  
**问题**: 以选项文本为 key，若两个选项恰巧内容相同（如两组不同题目的选项），会导致渲染问题。  
**建议**: 使用 `opt + '_' + currentQuestion.question_id` 作为 key。

### 2.13 [低] `setTimeout` 在组件卸载后仍执行

**文件**: `client/frontend/src/views/Register.vue:100`  
**问题**: 注册成功 1.5s 后 `router.push('/login')`。若用户在此期间导航离开，仍会执行跳转。  
**建议**: 保存 timer ID 并在 `onUnmounted` 中 `clearTimeout`。

## 3. 性能问题

### 3.1 [高] 考试记录列表 N+1 查询

**文件**: `exam-server/internal/service/exam_service.go:266-285`  
**问题**: 循环中为每条考试记录调用 `s.paperRepo.FindByID(r.PaperID)`。50 条记录产生 51 次数据库查询。另外 line 303 也存在同样的 N+1。  
**建议**: 先收集所有 PaperID，用单次 `WHERE IN` 批量查询。

### 3.2 [高] 成绩统计三层嵌套循环

**文件**: `exam-server/internal/service/grade_service.go:364-374`  
**问题**: 
```go
for _, r := range records {
    for _, d := range allDetails[r.ID] {
        if d.QuestionID == q.ID {
```
100 条记录 × 50 详情 × 50 题目 = 250,000 次内层迭代。  
**建议**: 建立 `map[uint64][]model.AnswerDetail` 以 QuestionID 索引。

### 3.3 [中] 提交试卷逐条更新答案

**文件**: `exam-server/internal/service/exam_service.go:230-235`  
**问题**: 每题一个独立 UPDATE 语句，N 题产生 N 次 DB 往返。

## 5. 架构问题

### 5.1 [高] Service 层绕过 Repository 直接操作数据库

**文件**: `exam-server/internal/service/exam_service.go`  
- line 42: `database.DB.Model(&model.Paper{}).Where(...)`
- line 58: `database.DB.Model(&model.ExamRecord{}).Where(...)`  
- lines 230-235: `database.DB.Model(&model.AnswerDetail{}).Updates(...)`  
**问题**: 破坏了 Controller → Service → Repository → Model 的分层架构。绕过 Repository 意味着无法 mock 数据库进行单元测试，业务逻辑与 GORM 强耦合。  
**建议**: 将所有数据库操作移至对应的 Repository。

### 5.2 [高] 无接口定义，无法单元测试

**问题**: 整个项目未定义任何接口。所有依赖通过具体构造函数注入（如 `repository.NewQuestionRepo()`），无法 mock。  
**影响**: 无法编写单元测试，所有测试必须依赖真实数据库。  
**建议**: 为 Repository 和 Service 定义接口。

### 5.3 [中] 全局可变状态

**文件**: 
- `exam-server/config/config.go:42` — `var AppConfig *Config`
- `exam-server/internal/database/db.go:15` — `var DB *gorm.DB`
- `exam-server/internal/cache/answer_cache.go:27` — `var GlobalCache *AnswerCache`  
**问题**: 三处全局变量贯穿全代码库。难以测试、难以推理并发安全、阻碍依赖注入。  
**建议**: 使用依赖注入模式，在 `main.go` 中构造并传递依赖。

### 5.4 [中] scripts 包非独立脚本

**文件**: `exam-server/scripts/seed.go`  
**问题**: 该包被 `cmd/server/main.go` 导入并在启动时调用，不是独立脚本。属于应用初始化代码，应放在 `internal/` 下。  
**建议**: 移至 `internal/seed/` 或改为 CLI 子命令。

### 5.5 [中] `pkg/errcode` 实际是内部包

**文件**: `exam-server/pkg/errcode/errcode.go`  
**问题**: Go 约定 `pkg/` 用于可被外部导入的代码。`errcode` 与业务领域紧密耦合（考试记录、试卷、题目等错误码），不应放在 `pkg/`。  
**建议**: 移至 `internal/errcode/`。

### 5.6 [中] 服务层返回值风格不统一

**问题**: 部分方法返回 `(data, int, error)`，部分返回 `(int, error)`，部分不返回值。`int` 始终是错误码。风格不一致。  
**建议**: 统一用 `(data, error)` 并通过自定义错误类型携带错误码。

## 6. Go 最佳实践

### 6.1 [中] 未传播 HTTP 请求上下文

**问题**: 所有 Repository 方法均不接受 `context.Context`，GORM 的 `db.WithContext(ctx)` 未被使用。数据库查询无法被上游请求超时取消。  
**建议**: 从 Controller 开始传递 `c.Request.Context()` 到 Repository 层。

### 6.2 [中] 未使用错误包装（Error Wrapping）

**问题**: 全代码库错误用 `errors.New(...)` 创建，下层错误未用 `fmt.Errorf("...: %w", err)` 包装。错误链丢失，调试困难。  
**建议**: 在所有 Repository 和 Service 层使用 `%w` 包装错误。

### 6.3 [中] `log.Fatalf` 在库代码中使用

**文件**: `exam-server/internal/database/db.go:31,36,43,59`  
**问题**: `database.Init` 和 `AutoMigrate` 调用 `log.Fatalf`（执行 `os.Exit(1)`）。在包层级终止进程是糟糕实践，阻止调用者优雅处理错误。  
**建议**: 返回 error，由 `main.go` 决定是否退出。

### 6.4 [低] 使用 `chan struct{}` 而非 `context.Context` 管理生命周期

**文件**: `exam-server/internal/cache/answer_cache.go:24`  
**代码**: `stopCh chan struct{}`  
**建议**: 使用 `context.Context` 以支持取消信号传递。

### 6.5 [低] 延迟关闭 excelize 文件的时机不当

**文件**: `exam-server/internal/service/grade_service.go:462-518`  
**代码**: 
```go
f := excelize.NewFile()
defer f.Close()  // line 462
...
buf, err := f.WriteToBuffer()  // line 518
```
**问题**: `defer f.Close()` 在创建文件后立即注册，但 `WriteToBuffer` 在其后调用。虽然 excelize 是内存操作大概率正常，但模式不正确。  
**建议**: 将 `defer` 放在实际使用后。

## 7. Vue/TS 最佳实践

### 7.1 [中] 大量使用 `any` 类型

**问题**: 所有 `catch` 块使用 `(err: any)`，违反 TS 最佳实践（应使用 `unknown`）。  
**文件**: `Login.vue:80`, `Register.vue:104`, `QuestionForm.vue:121`, `QuestionImport.vue:103` 等  
**建议**: 使用 `catch (err: unknown)` 并通过类型守卫窄化。

### 7.2 [中] 使用 `as any` 绕过类型检查

**文件**: 
- `client/frontend/src/views/admin/UserManagement.vue:196` — `{ status: newStatus } as any`  
- `client/frontend/src/views/admin/OperationLogs.vue:68` — `const params: any = { ... }`  
**建议**: 使用正确的接口类型。

### 7.3 [中] 本地重新定义 API 接口

**文件**: 
- `OperationLogs.vue:52-54` — `interface LogItem`（已存在于 `@/api/admin`）  
- `UserManagement.vue:88-90` — `interface UserItem`（已存在于 `@/api/admin`）  
**建议**: 导入并使用 API 层定义的类型。

### 7.4 [中] 全局 loading 状态冲突

**文件**: `stores/exam.ts:24`、`stores/grade.ts:21`  
**问题**: 单个 `loading` ref 被多个异步操作共享。`ExamRecords` 组件调用 `fetchRecords` 时，若 `fetchPapers` 仍在进行，`loading` 一直为 true。  
**建议**: 为每个操作独立维护 loading 状态，或使用操作队列。

### 7.5 [低] deep watcher 导致过多 localStorage 写入

**文件**: `client/frontend/src/views/student/ExamTaking.vue:392`  
**代码**: `watch(answers, saveAnswersToLocal, { deep: true })`  
**问题**: 每次答题操作都触发 localStorage 写入，文本题有 500ms 防抖但 watcher 仍会额外触发。  
**建议**: 使用 `watchEffect` 或在保存前合并变更。

### 7.6 [低] `URL.createObjectURL` 缺少 try/finally

**文件**: `client/frontend/src/views/teacher/Statistics.vue:133-141`  
**问题**: `a.click()` 若抛出异常（某些浏览器环境），`URL.revokeObjectURL(url)` 不会执行。  
**建议**: 包裹在 try/finally 中。

### 7.7 [低] 布局文件脚本部分完全相同

**文件**: `AdminLayout.vue`, `StudentLayout.vue`, `TeacherLayout.vue`  
**问题**: 三个布局的 `<script setup>` 除了侧边栏数据外完全一样：
```ts
import { useRouter } from 'vue-router'
import { useAuthStore } from '@/stores/auth'
const router = useRouter()
const authStore = useAuthStore()
function handleLogout() { ... }
```
**建议**: 抽取为 `useLogout` composable。

## 8. UX 问题

### 8.1 [中] 无全局通知/Toast 系统

**问题**: 错误反馈通过三种不同方式传递：
- `alert()` 弹窗（UserManagement、AvailablePapers、PaperList 等）
- 内联 `errorMsg` 变量（Login、QuestionForm、Register）
- 静默吞掉（OperationLogs、TeacherDashboard）

无统一的通知组件，用户体验割裂。  
**建议**: 构建 `useNotify()` composable + `<ToastProvider>` 组件。

### 8.2 [中] 列表页缺少错误状态

**文件**: `OperationLogs.vue:25-26`, `QuestionList.vue:50-54`, `PaperList.vue:42-46`, `UserManagement.vue:22-23`  
**问题**: 模板只区分"加载中"和"空数据"，API 调用失败时用户看到"暂无数据"而非错误提示。  
**建议**: 增加 `error` 状态并在 UI 中显示错误信息。

### 8.3 [低] 考试自动交卷无提示

**文件**: `client/frontend/src/views/student/ExamTaking.vue:317-321`  
**问题**: 时间到时自动提交，无 60 秒倒计时警告。学生可能在输入中被中断。  
**建议**: 剩余 60 秒时弹出警告或闪烁倒计时。

### 8.4 [低] 无考试中离开确认

**文件**: `client/frontend/src/router/index.ts:147`  
**问题**: `ExamTaking` 路由设置了 `meta: { exam: true }` 但 `beforeEach` 守卫未利用该标志。学生可能误触导航离开考试。  
**建议**: 在 `ExamTaking.vue` 中添加 `onBeforeRouteLeave` 守卫。

### 8.5 [低] 分页大小不可调

**问题**: 所有列表视图的 `pageSize` 硬编码为 10 或 15。无 10/20/50 下拉选择。  
**建议**: 增加每页条数选择器。

### 8.6 [低] 缺少加载骨架屏

**问题**: 所有加载状态使用简单文本"加载中..."，无骨架屏或进度条。  
**建议**: 使用骨架屏组件替代文本提示。
